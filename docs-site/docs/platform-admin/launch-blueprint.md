# Launch Blueprint

Launch Blueprint prepares tenant setup before final launch readiness review.

## Purpose

Use Launch Blueprint to apply guided setup choices, optional add-ons, and baseline configuration for a tenant before handoff.

## Use this page when

- A tenant needs country or domain defaults.
- Optional launch add-ons should be selected before setup is applied.
- Baseline leave, attendance, policy, or organization setup needs an operator review.
- A setup blueprint needs to be upgraded or reapplied with evidence.

## Page sections

| Section | Meaning |
| --- | --- |
| Tenant selector | Choose the tenant that should receive blueprint setup. |
| Blueprint options | Select default and optional setup areas for the launch scope. |
| Readiness summary | Shows missing choices, applied setup, and blockers. |
| Apply controls | Applies or upgrades launch setup only when required choices are valid. |
| Evidence notes | Records what was selected and why the setup was applied. |

## Good practice

- Select only the optional add-ons that are intentionally in scope for the tenant.
- Review the tenant record before applying setup.
- Confirm blueprint output in Launch Readiness before handoff.
- Keep payroll-impacting choices aligned with the payroll launch owner.

## FAQ

### Is Launch Blueprint the same as Launch Readiness?

No. Launch Blueprint prepares setup. Launch Readiness verifies gates, handoff, blockers, and activation evidence.

### Can optional add-ons be enabled later?

Yes. Add-ons should be enabled only when the tenant has accepted the scope and the owner understands any payroll or workflow impact.
