# Manager Self Service User Guide

Date: 2026-09-13

## Purpose

The Manager uses MSS to review and act on team requests. The manager should be able to approve or reject leave, attendance, and employee workflow items for direct reports only.

## Main Workspace

- Primary route: `/mss`
- Approvals: `/mss/approvals`
- Notifications: `/mss/notifications`

## What The Manager Can Do

- View team-related approvals.
- Approve or reject requests.
- Review request details before action.
- Add comments where required.
- Review notifications.
- Confirm pending and completed approval states.

## What The Manager Should Not Do

- Do not approve requests without reviewing dates and reason.
- Do not approve requests outside your reporting hierarchy.
- Do not edit employee salary, statutory, or payroll calculation data.
- Do not use HR Admin pages unless assigned HR Admin access.

## First Login Checklist

1. Open MSS workspace.
2. Confirm your name and manager role.
3. Open approvals.
4. Confirm pending items load.
5. Open notifications.
6. Confirm no HR Admin or Platform Admin data is visible.

## Approval Workflow

1. Open Approvals.
2. Select a pending request.
3. Review employee name.
4. Review request type.
5. Review request dates and duration.
6. Review reason and attachments if available.
7. Check balance or policy warning if shown.
8. Approve if valid.
9. Reject with a clear reason if invalid.
10. Confirm the item moves out of pending list.

## Negative Scenario Checks

If a request looks wrong:

- Missing reason: reject or request clarification.
- Date conflict: reject or ask HR to review.
- Employee not in your team: escalate access issue.
- Duplicate request: do not approve twice.
- Policy warning: approve only if your company policy allows override.

## Common Issues

| Issue | What to check |
| --- | --- |
| No approvals visible | Reporting manager mapping and pending request availability |
| Wrong employee visible | Reporting hierarchy setup |
| Approve button disabled | Required comment, status, or policy validation |
| Notification not updated | Refresh and verify request status |

## Completion Criteria

An approval task is complete when:

- Request was reviewed.
- Decision was recorded.
- Comment was added when needed.
- Status changed correctly.
- Employee and HR can see the updated status.
