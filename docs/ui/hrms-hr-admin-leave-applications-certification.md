# HR Admin Leave Applications standardization

Date: 2026-10-20. Scope: `/hr-admin/leave-requests`, its selected-request panel, existing HR override dialog and import entry point. This is the first Leave Management slice, not certification of the entire Leave family. Local tested functionality: **PASS**. Overall slice certification: **CONDITIONAL**, with the limits below. No deployment or production certification.

## Implementation and contract review

The page now opts into the same `accerio-page`, `PageIntro appearance="accerio"`, semantic tokens, shared shell, table-scroll region, filter form, pagination, status badges, loading/error boundaries and HR action modal used by Attendance. No new stylesheet, component library, dependency or migration was added. The existing centralized stylesheet receives only the inline-review action-flow override. Changed application files are the page, queue, override form, new route loading/error boundaries and the shared backend option serializer; QA/configuration/documentation files accompany them. Navigation and import utilities use compact disclosures. Details open only after an explicit selection; the current request is URL-addressable. The original request fields, approval history, collision evidence and balance navigation remain available.

Source references:

- [Page and permission boundary](../../web/src/app/hr-admin/leave-requests/page.tsx): `leave.view`; review actions retain `leave.requests.approve`.
- [Queue](../../web/src/app/hr-admin/leave-requests/leave-request-queue.tsx): committed URL state, named GET controls, explicit details and table semantics.
- [Override form](../../web/src/app/hr-admin/leave-requests/leave-request-override-form.tsx): unchanged approve/reject payload and server validation; fresh-document return only after success, retaining the duplicate-submit guard during navigation.

List supports `q`, `status`, `leave_type_code`, overlapping `from_date`/`to_date`, page and page size up to 100; order remains newest first. `status_counts` are tenant-wide rather than filter-scoped.
- [Shared filter form](../../web/src/components/patterns/workspace-filter-form.tsx), [pagination](../../web/src/components/patterns/pagination-bar.tsx), [table scrolling](../../web/src/components/patterns/workspace-table-scroll-region.tsx), [modal](../../web/src/components/patterns/hr-admin-action-modal.tsx), [central styles](../../web/src/styles/workspace-patterns.css).

Existing option entries without codes retain their prior fields and null metadata. Request parameters, approval eligibility, RBAC, tenant scoping, audit services, balance calculations and historical-close protections are unchanged. Detail reads use the existing server-to-backend contract; there is no new frontend detail API route. Foreign-ID detail verification calls that real backend endpoint. There is no new sorting or universal approval policy.

## Defects and remediation

| Finding | Classification | Remediation / evidence |
|---|---|---|

| First request opened automatically; selection lived separately from the URL | Application interaction inconsistency | URL-owned selection; no automatic first-row detail, and filter/page changes omit old selection. |
| Uncontrolled filter controls could retain defaults across history restoration | Application form integration defect, reproduced in all three engines | Key only the shared filter subtrees by committed scope; preserve business edit forms. |
| Clear Filters entered shell client-navigation feedback and stalled in WebKit | Application navigation integration defect | Use the shared explicit document-navigation opt-out on clear links. First repaired matrix retained 20 passes / 1 failure before this change. |

No server request is needed to dismiss presentation. Initial focus, containment, Escape and opener restoration are retested at desktop and small-screen sizes. The exact internal browser/React scheduling trigger is not proven. |
| Successful HR rejection could leave the override dialog present in Chromium | Application navigation/refresh race | `push` followed immediately by `refresh` could refresh the old override URL. Return with fresh document navigation after success. Other engines also verify the real successful rejection and backend state. |

This avoids dependence on button hydration/client route commits for query navigation. Exact internal scheduling trigger remains unproven. |

| Desktop filters stacked vertically in the first candidate screenshot | Presentation integration defect | Restore the existing shared filter-bar class; no page-specific CSS added. |
| Matching total appeared alongside unqualified tenant status totals and page-local blocking count | Misleading scope labels | Explicit matching, tenant and on-this-page labels. Partial approval uses warning rather than completed-success presentation. |
| Date-only formatting depended on runtime timezone | Presentation risk | Format date-only fields in UTC; existing Asia/Kolkata timestamp display remains unchanged. No new tenant timezone policy. |
| Global alert locator matched the Next route announcer; test requested a nonexistent frontend detail route | Test harness defects | Scope the validation alert to main and verify the actual backend detail endpoint with the synthetic session token. Do not count route-not-found as ownership enforcement. |
