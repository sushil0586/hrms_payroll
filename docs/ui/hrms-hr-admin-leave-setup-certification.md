# HR Admin Leave Types, Policies and Assignments

Date: 2026-10-20. Scope: the three catalogs, their existing create/edit routes and dialogs, and authorized removal/governance workflows. Local synthetic-only implementation. Local tested functionality **PASS**; overall scoped certification **CONDITIONAL**; no staging deployment or whole-HR Admin certification.

## Findings and implementation

- Types and Policies used immediate local filters with nonfunctional Apply buttons. Both backend endpoints return the full tenant-authorized catalog (not a paginated subset). Named shared GET forms now commit on Apply/Enter, retain filters on refresh and history, and clear explicitly. No new server filtering contract is invented.
- Detail panels opened automatically and used transient local selection. Named native Inspect/Close links now preserve filter context in the URL. Create/edit modals retain context on save/close. Successful saves perform document navigation to fetch authoritative data rather than restoring a cached catalog.
- Assignment filters continue to use the backend paginated contract, with out-of-range URL normalization, accurate nonstandard row-size representation and explicitly page-scoped risk metrics. Effective dates are shown in the detail panel; missing starts are labelled Not recorded rather than inventing legacy classification.
- Shared Accerio page headers, surfaces, status badges, table styles, named keyboard-scroll regions and compact context/governance disclosures replace inconsistent page chrome. Tables/filters precede advanced governance utilities. Existing standalone create/edit routes receive the same page header language. No new component library, page stylesheet, business calculation, endpoint or payload schema. The Leave Type duplicate-code error is corrected from HTTP 500 to a field-validation HTTP 400.
- Policy impact fetch had no transport-error handling and could remain loading indefinitely. It now settles loading/error state, prevents unsafe actions without impact data, supports close/reopen recovery and ignores stale responses from an earlier dialog.
- Validation/governance text inside labels changed accessible input names after errors. Explicit stable names were added to existing labelled form controls; visible labels, validation and governance restrictions remain intact.
- A legacy modal selector hid the policy form header, including its real Preview policy action. A shared actionable-header modifier preserves functional actions while omitting the redundant heading. Nested-dialog key handling is scoped to the nearest dialog, preventing the outer form from handling a preview's Tab/Escape events.
- Types/assignment action components are keyed to the selected record so a previous record's local feedback/dialog state cannot be carried into a different selection.

- Real duplicate Leave Type create/edit codes previously reached the database uniqueness constraint as HTTP 500. `save_hr_admin_leave_type` now validates within tenant scope, excludes the current record during edits, and maps only the tenant/code uniqueness violation in a savepoint-protected insert race to a code-field validation error. Unknown integrity errors propagate. The constraint remains enabled; no migration, calculation or permission change.
- Assignment imports now refresh authorized server catalog counts after actual created rows, including partial-success responses. The existing parser, import endpoint, partial-commit audit behavior and policy rules remain intact. Empty policy selection no longer falsely reports an active overlap check.

- A focused fast-edit trace showed the priority input changed to 778 while the PATCH body still carried 777: server-rendered controlled fields accepted edits before handlers were hydrated. Shared `WorkspaceFormControls` keeps the three forms disabled through hydration; no sleeps, assertion relaxation or mutation-policy change. Authenticated server HTML is parsed inertly to verify disabled/busy readiness gates; hydrated forms are then checked for editability. A JavaScript-disabled modal attempt exposed Next streaming visibility limitations and is preserved as a harness limitation, not counted as an executed no-JavaScript product acceptance.
