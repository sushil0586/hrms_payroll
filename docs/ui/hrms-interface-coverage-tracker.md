## Approved Standard

The approved standard is compact, table-first, and operational:

- Compact page header with primary actions on the right.
- Clear navigation/sidebar grouping without secondary truncation.
- Internal work pages must follow the structural standard, not just the visual tokens: compact summary strip, compact filter toolbar, working table/list grid, selected-row highlight, and detail drawer or focused side panel.
- Avoid stacked record-card pages for operational queues when records are comparable; use a visible table as the primary working surface.
- Move secondary metadata and long detail grids out of rows and into the detail drawer/panel.
- Visible working tables with readable 14px primary and 12-13px secondary text.
- Compact toolbar filters with Search, key selects, More filters, Apply, and Reset/Clear.
- Right-side inspection drawer for selected records where appropriate.
- Standard status and review badges with consistent colors and plain language.
- Guided modal forms with clear title, short helper text, fixed header/footer, body-only scroll, focus trap, Escape close, focus restoration, dirty-change confirmation, required markers, inline validation, and responsive width.
- Cancel, Back, Continue, and final Save/Create on the final step for guided forms.

## Internal Page Instruction Set

Apply this to every internal page across HR Admin, ESS, MSS, Tenant Admin, and Platform Admin unless the page is a pure dashboard or static report:

1. Use a compact page header: title, one-line description, and primary actions aligned right.
2. Replace KPI-card rows with a compact summary strip when metrics are page context rather than decision cards.
3. Make the primary work area table-first:
   - Use real tables for comparable records.
   - Keep row text concise.
   - Use 14px primary text and 12-13px secondary text.
   - Give the main name/title column enough width.
4. Use a compact toolbar directly above the table:
   - Search first.
   - Then the most important 2-3 filters.
   - Put secondary filters behind More filters where needed.
   - Keep Apply and Reset/Clear actions consistent.
5. Preserve selected-row highlighting.
6. Show record details in a closable drawer or side panel:
   - Profile/summary first.
   - Group details into compact sections.
   - Keep action buttons in the drawer header.
   - Put long metadata, audit/history, and notes in the drawer, not in the table row.
   - Drawer actions that open child create/edit/review workflows should open the standardized modal popup and preserve queue context; legacy full pages are fallback only during migration.
7. Use standard badges for statuses, review states, readiness, and risk.
8. Use modals only for focused create/edit/action flows:
   - Long create/edit forms use guided steps.
   - Short forms use simple grouped layouts.
   - All modals use fixed header/footer, body-only scroll, required markers, inline validation, focus trap, Escape close, focus restoration, and dirty-change confirmation.
9. Preserve every existing field, action, permission, validation, API integration, and business rule. Do not copy prototype simplifications into production flows.
10. Verify every migrated internal page at desktop, tablet, and mobile widths with browser automation, including no horizontal page overflow.

## Priority Rules

| Priority | Criteria |
| --- | --- |
| High | Forms, modal/dialogs, drawers, create/edit/review screens, permission-sensitive workflows. |
| Medium | Tables, queue pages, dashboards, filter-heavy pages. |
| Low | Static hubs, report landing pages, loading/error pages. |

## Workspace Migration Plan

1. Freeze the employee directory and employee modal as the reference benchmark.
2. Migrate high-risk modal/form flows first: HR Admin employee access/bank, leave policy preview/delete, attendance regularization review, ESS leave/document/statutory dialogs, MSS approval dialogs, Tenant membership/role dialogs, Platform tenant/admin dialogs.
3. Migrate queue/table pages next using `WorkspaceFilterBar`, `WorkspaceDataTable`, and `WorkspaceStatusBadge`.
4. Normalize dashboard/hub pages using `WorkspaceStandardHeader` and `WorkspaceStandardPanel`.
5. Run desktop/tablet/mobile screenshot verification for every migrated route.
