## Source interaction risks requiring executed checks

The four lifecycle forms use separate submitting state, disable the save button and call `router.push` followed by `router.refresh` on success. Their fetch paths and child Cancel/navigation behavior do not yet share the later Documents draft/pending/outcome contract. Source inspection suggests network, concurrent-submit, dirty-navigation and return-navigation gaps; **these failures were not reproduced by this read-only baseline**. Adopt the established contract and test it rather than assuming the shared modal protects every child action.

Onboarding/checklist and exit/clearance writes can create or refresh template work items, history and notifications. Probation confirmation/extension can update employee dates. Completed movement calls the effective-history service and can update current employee mappings. Exit saves validate chronology/clearance and synchronize workflow/employee state. These are domain side effects to preserve and independently verify, not styling details or newly authorized policy changes.

Organization import preview is local to the browser; ready rows are created through existing calls. Guided setup creates/reuses dependencies sequentially. Expanded workbench rendering, partial outcomes, retry behavior and real persistence are still Phase 2 gates. Neither is accepted as atomic or idempotent based on current captures.

## Acceptance limits and cleanup

Baseline coverage includes all 18 route patterns and all nine section editor variants, existing create/edit dialogs, no matches, stale selection and an authorized off-page edit. It does not include expanded guided/import flows, genuine empty tenant, unavailable service reads, stale standalone details, all inbox detail/edit states, browser-history interactions, keyboard/dirty/pending/validation/recovery, writes, actual export files, other browser engines or formal assistive technology/native-zoom/physical-device review. Relevant implementation phases must close those gates before their scoped acceptance.

The fixture tenant and recorded temporary context were removed. Final Tenant, User, Employee, Onboarding, ProbationReview, Movement and Exit counts were zero in the isolated database. No owned stored files remained and no export audit rows were created. Repository audit hashes stayed unchanged. Exact backend/Next processes, owned Postgres container/volume, private runtime and temporary runner were removed; ports 55472/8073/3273 were free. Runtime/test/backend contract manifests had zero mismatches, including unchanged `backend/apps/common/api_serializers.py`. The accepted production build remains available. No runtime code change, commit or deployment was performed; notifications were disabled and email stayed local.
